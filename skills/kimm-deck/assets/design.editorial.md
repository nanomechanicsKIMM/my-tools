# 에디토리얼 보고 덱 (design.editorial)

**언제 이 양식인가**: 청중을 설득해야 하는 자리 — 발표, 심의, 경영층 보고.
표·항목 나열이 아니라 **슬라이드당 메시지 1개**를 세우고, 수치를 그림으로 증명한다.

**언제 design.kimm인가**: 기록·배포용 4:3 보고서 덱. 항목을 빠짐없이 담아야 할 때.

> 두 시스템은 좌표계가 다르다 — **혼용 금지**. 한 덱은 하나의 시스템으로만 만든다.

---

## 1. 페이지 기하

| 항목 | 값 |
|---|---|
| 슬라이드 크기 | **13.333 × 7.5 in (16:9)** |
| 좌측 여백 `M` | 0.75 in · 우측 끝 `R` 12.58 in |
| 라벨 컬럼 | x 0.75, 폭 2.05 — 섹션 키커 + `nn / NN` 페이지만 |
| 콘텐츠 컬럼 | x 3.10, 폭 9.48 (헤드라인·부제 기준선) |
| 헤더 헤어라인 | y 1.52, 폭 `R − M` |
| 콘텐츠 영역 | y 1.78 – 6.35 |
| 결론 스트립 | y 6.52, 좌측 바 0.09 × 0.46 |
| 푸터 | 헤어라인 y 7.12 + 10 pt 캡션 y 7.19 |

전면 폭을 쓰는 슬라이드(그림·막대·스케일)는 라벨 컬럼 아래 영역까지 침범해도 된다 —
라벨 컬럼은 헤더에서만 지켜진다.

## 2. 색상 토큰

| 토큰 | HEX | 용도 |
|---|---|---|
| `INK` | `14161A` | 헤드라인·본문 — **지배색** |
| `DEEP` | `10263A` | 구조색 : 표지 세로 룰 · 기준선 · 목표 창 |
| `MUTE` | `8A9099` | 부제·축·캡션 |
| `RULE` | `D8D4CC` | 헤어라인 |
| `WASH` | `F3F1ED` | 강조 패널 바탕 |
| `TEAL` | `0E7C86` | **달성·일치** |
| `CORAL` | `D1495B` | **미달** |
| `AMBER` | `E09F3E` | **진행·주의** |
| `GRAYBAR` | `C9CCD1` | 기준(목표·논문) 막대 |

**의미색은 3종뿐이다** (청록·코랄·앰버). 나머지는 전부 무채 계열 — 색이 적을수록
상태 판정이 선명해진다. design.kimm의 6색 상태 팔레트를 그대로 옮겨오지 말 것.

## 3. 타이포그래피

| 요소 | 크기 | 스타일 |
|---|---|---|
| 표지 제목 | 44 pt | Bold, 2줄, `line_spacing 1.12` |
| 슬라이드 헤드라인 | 30 pt | Bold — **결론을 그대로 쓴다** ("방법은 재현됐다") |
| 부제 | 15 pt | `MUTE`, 헤드라인을 한 문장으로 보충 |
| 섹션 키커 / 페이지 | 13 / 12 pt | Bold, `TEAL` / `MUTE` |
| 대형 스탯 숫자 | 46 pt | Bold, Trebuchet MS (라이닝 숫자) |
| 본문 | 13–14 pt | — |
| 결론 스트립 | 19 pt | Bold, 의미색 |

폰트는 **Trebuchet MS**(숫자·라틴)와 테마 한글 기본만 쓴다. Georgia 등 세리프는
숫자가 올드스타일로 조판돼 데이터 슬라이드에서 읽기 나빠진다 — 쓰지 말 것.

## 4. 슬라이드 아키타입

### A. 표지 (`cover`)
좌측 세로 룰(`DEEP`, 0.16 × 3.20) + 키커/날짜 → 대형 제목 2줄 → 부제 →
헤어라인 → **메타 4열**(라벨/값/부연) → 헤어라인 → 한 줄 주장(24 pt, 뒷절만 `CORAL`).

### B. 대형 스탯 4열 (`stat`)
규모·실적을 숫자로 먼저 때린다. 46 pt 숫자 + 단위 + 15 pt 라벨 + 13 pt 부연 2줄.
부연은 **한 줄 안에 끝낼 것** — 2줄로 꺾이면 4열의 리듬이 깨진다.

### C. 이중 막대 (`bar_head` + `bar_row`)
기준(회색, 위) vs 우리(의미색, 아래) 한 쌍이 한 행. 우측에 값과 판정.
- 길이는 **행마다 따로 정규화**한다. 행끼리 길이를 비교하는 그림이 아니다.
- 지표 방향이 섞이면 항목명에 `↓`(작을수록 좋음)·`↑`(클수록 좋음)를 붙이고
  각주에 범례를 단다. 방향 표시 없이 섞으면 반드시 오독된다.
- **범위(산포)와 단일값을 같은 막대 축에 그리지 말 것** — 산포는 D의 스케일로.

### D. 실축척 스케일 (`scale`) — 이 시스템의 핵심 장치
목표 창과 실제 산포를 **같은 축에 비율 그대로** 그린다.
- 목표 창(`band`)의 폭이 곧 허용오차다. 보이라고 임의로 굵게 그리면 그림이 거짓이 된다.
- 산포(`span`)는 굵은 막대. 라벨은 막대 위, 목표 캡션은 축 아래에 둔다(겹침 방지).
- "산포가 허용오차의 N배"라는 문장을 **눈으로 확인시키는 것**이 목적이다.

### E. 진단 카드 (`card`)
번호 → 제목 → 판정 한 줄(의미색) → 근거 3–4줄 → **다음 수**(WASH 박스).
원인마다 대책을 붙여야 "남은 문제"가 "실행 계획"으로 읽힌다.

### F. 수직 타임라인 (`timeline`)
시점(의미색) + 제목 + 설명 한 줄. 설명은 배치 폭에 맞춰 **한 줄로 줄인다**.

### G. 강조 패널 (`panel`)
WASH 바탕 + 제목 + 3줄 이내. 규율·전제·요약처럼 '읽고 넘어가는' 정보 전용.

## 5. 작성 수칙 (실제로 깨졌던 항목)

- **헤드라인 = 결론**. "결과"가 아니라 "방법은 재현됐다"로 쓴다.
- 텍스트 박스는 배치 위치에서 **우측 마진까지의 남은 폭**으로 잡는다. 헬퍼에
  고정 폭을 박아두면 오른쪽 배치에서 캔버스를 넘는다(`timeline` 실제 사고).
- 카드 내부 요소는 **카드 높이에서 역산**한다. 본문 높이를 고정하면 짧은 카드에서
  '다음 수' 박스와 겹친다(`card` 실제 사고).
- 축·막대 주변 라벨은 **위/아래로 분리**한다. 같은 y에 두면 문자끼리 충돌한다.
- 표지 제목이 2줄이면 부제를 3.6 in 아래로 내린다 — 44 pt 2줄은 1.6 in을 먹는다.
- 저장은 반드시 `save()` — python-pptx 도형의 테마 그림자(`<p:style>`)를 제거한다.
- 생성 후 **`audit()`를 돌려 캔버스 이탈·그림자·비번들 폰트 0건을 확인**하고,
  렌더 QA(`soffice` → `pdftoppm`)로 전 슬라이드를 육안 검수한다. 최소 1회
  수정-재검증 사이클 전에는 완료로 보고하지 않는다.
