# 필드 작성 가이드

각 필드의 **의미·표기 관행·자주 하는 실수**를 정리한다. 스킬이 사용자에게 기본값을 제시할 때 참고한다.

## 식별 정보

### 품명 (Description)
- 무엇을 사는지 한 문장으로. 브랜드+모델까지 적는 것이 일반적. 예: `Apple MacBook Pro 14 (M5 Max)` / `Minitab Single-User Annual License (서브스크립션)` / `AutoCAD LT`
- 견적서 표 첫 행을 그대로 가져오되 줄바꿈은 한 줄로 합친다.

### 규격 (Specification)
- 핵심 사양을 콤마 구분 한 줄. 예: `M5 Max(18C/40C/16NE), 128GB, 2TB SSD`
- 본문(규격서 sections)에서 더 상세히 풀기 때문에 여기서는 한 줄 요약.

### 모델명
- 제조사 모델명 (HSK 신고용). 모델이 따로 없으면 `-`.

### HSK 코드
- 수입 세번. 국내 조달이면 보통 `-` 처리.
- 노트북 일반: `8471.30-0000`. 데스크톱: `8471.50-0000`. SW: `-` 또는 `8523.49`. 반드시 사용자에게 확인.

## 금액

### 수량 / 단위
- "수량 + 공백 + 단위". 예: `1 EA`, `2 식`, `5 유저`.

### 금액
- 견적서의 **합계금액**. 부가세 포함 여부 명시. 예: `9,900,000원 (부가세 포함)`.
- 조달 수수료가 별도로 있으면 괄호로 추가. 예: `1,147,300원 (조달수수료 6,160원 포함)`.

## 과제 정보 (구매 건마다 변동)

### 연구명
- 풀 과제명. 보고서/계약서에 기재되는 정식 명칭을 사용.
- 4차년도 보고서명 등 회계연도별로 다를 수 있으니 사용자에게 확인.

### 연구기간
- `YYYY.MM.DD.-YYYY.MM.DD` (점·하이픈 패턴). 보통 회계연도 단위.

### 연구책임자
- 성명 한 줄. 직책/소속 표기 안 함.

### 자금명
- 형식: `<자금 종류>(<사업코드>)`. 예: `연구비(NK266F)`. 사업코드는 매년 부여번호가 다르므로 사용자에게 확인.

### 부서명
- 구매요구 부서명. 정식 부서명 사용.

## 활용 정보

### 활용예상빈도
- `XX시간/년` 형태. 노트북/PC 는 `1500~2000시간/년` 이 흔함 (주 30~40h × 50주).

### 기보유량 / 공동활용
- 기관 D/B 조회 결과. 보통 `확인 불가능` 또는 보유 수량 표기.
- 공동활용은 `없음` / `있음 - 부서명` / `예정` 등.

### 장비구분
- 일반연구장비 / S/W 라이센스(N년) / 시설 / 비품 등.
- 노트북은 보통 `컴퓨터/노트북 (일반연구장비)`.

### 설치 사용 장소
- 동·호실. 예: `연구11동 305호`. 출장 휴대용이면 부서 사무실로.

### 기타 특기 사항
- 보통 비워둠. 특수 도입 사유(긴급 / 단가계약 / 수입 / 기증 등) 있으면 한 줄.

## 본문 작성 (규격서 sections)

규격서 본문은 자유 섹션 구성이다. 일반 권장 구조:

### HW 장비 (PC/노트북/계측기)
1. 제품 개요 및 사용 목적 (2~4문장)
2. 주요 사양 (개조식 항목, 견적 규격에서 추출)
3. 공급 및 보증 조건 (납품기일, 보증, 호환성 등)

### SW 라이선스
1. 소프트웨어 개요 및 주요 기능 (1) 개요 + 2) 주요 기능 분류)
2. 라이선스 공급 방식 (ESD/물리매체, 사용자 수, 갱신 주기)
3. 시스템 요구사항 (OS/RAM/CPU/디스크/네트워크)

### 시약·소모품
1. 제품 사양 (CAS, 순도, 포장단위)
2. 안전관리 (MSDS 보유, 보관 조건)
3. 사용 계획

## 본문 작성 (용도설명서 용도개요)

**원칙: 4~5 문장. 상세한 표현. 개조식.**

기본 골격:

```
 본 과제 "{연구명}"에서는 {기술 분야 한 줄} 기술을 개발한다.
 - {연구 활동 1: vault 근거}
 - {연구 활동 2: vault 근거}
 - 본 장비는 {품명/모델}로서 {구체 활용 목적}에 사용한다.
 - {도입 효과 또는 대체 불가능성}
```

**Don't:**
- 추측·과장 표현 ("최첨단", "유일한", "혁신적")
- vault 에 근거 없는 기술적 주장
- 외부 웹 검색 결과 인용
- 4~5문장을 넘기는 장황한 서술

**Do:**
- vault (`brain/`, `LLM_work/report/`, `human/`) 의 노트에서 직접 발췌·요약
- 견적서 사양과 연구 요구의 연결을 명확히 (예: "통합메모리 128GB 가 필요한 이유는 ...")
- 대체 옵션을 검토했음을 암시 ("CUDA 의존 작업은 별도 GPU 환경에서 수행")
