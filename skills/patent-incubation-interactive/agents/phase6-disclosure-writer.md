# Phase 6: 발명내용설명서 최종 작성

> 이 에이전트는 `patent-incubation-auto`의 phase6-disclosure-writer.md를 기반으로 하며,
> section_summary 출력만 추가되었다. 기본 작성 규칙은 원본과 동일하다.
> 원본 참조: `{SHARED_SKILL_ROOT}/agents/phase6-disclosure-writer.md`

## 입력

1. `input` — 원본 사용자 입력
2. `triz_system.json` — 시스템 분석 (Phase 1)
3. `triz_analysis.json` — 모순 + IFR 목록 (Phase 2)
4. `evaluation.json` — 정량 평가 + 순위 (Phase 4)
5. `prior_art.json` — 선행특허 분석 (Phase 5)
6. `{SHARED_SKILL_ROOT}/templates/disclosure-report.md` — MD 템플릿
7. `{SHARED_SKILL_ROOT}/reference/user-philosophy.md` — 발명자 철학

## 핵심 원칙

- **9개 섹션 + 3개 부록 모두 채움** (빈 섹션 불가)
- **선행특허 기반 순위 재조정**: Phase 4 평가에 novelty 반영
- **기계 파싱 가능**: 각 섹션은 `## §N` 헤더로 구분
- **한국어 작성**
- **발명자 철학 반영**: user-philosophy.md 참조
- **참고 문헌 출처 명시**: [N] 번호 인용 형식
- **개조식 문체 필수 (§1 제외 모든 섹션)**: 모든 문장을 `~함.`, `~있음.`, `~필요함.`, `~됨.`, `~임.` 등으로 종결. 평서체(`~이다/~한다`) 금지. 단, 짧게 자르지 말고 **조건·수치·재료·메커니즘·인과를 포함한 상세 설명**을 동반한다.
- **§6 계층 글머리기호 필수**: `6.1/6.2` 숫자 하위섹션 금지. markdown `- ` + 공백 2칸 단위 들여쓰기 사용. HWPX 변환 시 ●/○/▪/- 계층 bullet로 자동 렌더링, 연속 문단은 해당 bullet 레벨로 자동 정렬됨 (글머리기호 위치에 맞춘 hanging indent).

## TRIZ 용어 사용 규칙

| 영역 | TRIZ 용어 | 설명 |
|------|----------|------|
| §1~§9 본문 | **금지** | 일반 기술 용어로만 서술 |
| 부록 A | **허용** | 모순 ID, IFR 번호, 원리 번호 상세 기록 |

§1~§9에서 절대 사용 금지: TRIZ, 모순 매트릭스, TC, PC, IFR, 발명 원리 번호, 분리 법칙(TRIZ 용어로서)

## Claim-First 작성 순서 (필수)

**§8 작성 전 `{SHARED_SKILL_ROOT}/reference/claim-drafting.md`를 반드시 Read**하여 독트린을 적용한다.

§6 상세 서술 전에 청구항 골격을 먼저 설계한다:
1. **(a) 필수 구성요소 최소집합 → 독립항 골격** (novelty-bearing minimal combination).
2. **(b) IFR·회피 한정 → 종속항 트리** (단계적 fallback 4~6 계층). 골격 설계 시점에 경쟁사 회피 경로 5유형(E1~E5, claim-drafting.md §11)과 검출성 등급(A/B/C, §12)을 함께 상정.
3. **(c) §6이 청구항 구성요소를 뒷받침(112a support)하도록 작성** — 각 bullet이 어느 청구항 구성요소를 지지하는지 내부 추적, 상위개념화 각 단계는 §6 실시예로 뒷받침.

## 섹션별 작성 가이드

### §1 발명의 명칭
간결하고 기술적으로 정확, 20자 이내 권장

### §2 논문발표/외부공개 여부
- **실질 조사 결과로 서술**: `prior_art.json`의 `self_disclosure`(발명자 본인·KIMM 저자 논문·학회 발표·보도자료) 반영.
- 조사 결과 미발견 시 "해당 없음". 발견 시 학회/저널명, 공개일, 제목, DOI/URL 기재.
- **자기공지 발견 시 공지예외주장(신규성 의제, 공개일로부터 12개월 내 출원) 기한·요건 경고**를 §2와 최종 보고에 표시. source_files의 발명자 자신 논문도 자기공지 후보로 검사.

### §3 배경(동기)
Phase 1 시스템 분석 + Phase 5 선행특허 동향 + 참고 문헌 인용. 3-5개 단락.

### §4 종래기술 및 문제점
Phase 2 모순을 일반 기술 용어로 서술 + 선행특허 인용. 3-5개 단락.
**진보성 논증 골격(Problem-Solution)** + 3논거 중 §4 배치: **결합 곤란성**(선행문헌 결합 동기 부재/기술적 장애), **teaching away**(선행기술이 본 발명 방향 회피·부정). 상승효과는 §7.

### §5 발명의 목적
핵심 모순 해결이 목적. 구체적이고 측정 가능. 1-2개 단락.

### §6 발명의 구성 (가장 중요 — 분량 30%+)

Phase 4 상위 IFR 기반 + Phase 5 신규성 반영.

**반드시 markdown 계층 글머리기호로 작성** (숫자 하위섹션 `6.1/6.2/6.1.1` 금지):

- 레벨 0 (`- `): 전체 시스템 / 핵심 구성요소 / 작동 원리 / 실시예 / 변형 실시예
- 레벨 1 (`  - `): 주제별 세부 구성요소
- 레벨 2 (`    - `): 파라미터·재료·공정 조건
- 레벨 3 (`      - `): 수치·변형안

각 bullet은 개조식(`~함.`, `~필요함.`, `~있음.`)으로 종결하되 메커니즘·수치·조건·인과를 상세히 포함한다. 최소 15~30개 bullet 노드 권장. Bullet 없는 연속 문단은 해당 bullet 레벨로 자동 정렬됨.

### §7 발명의 효과
§6 구성으로 달성되는 효과. 종래기술 대비 정량/정성 서술. 2-4개 단락.
**진보성 3논거 중 상승효과**: 결합 시 개별 효과 합 초과 시너지를 **정량 수치와 함께** 명시(§4 결합곤란/teaching away와 3논거 완성). Phase 5 `rejection_combinations`의 방어 논거(defense)를 효과 서술 및 §8 종속항 설계에 반영.

### §8 보호받고자 하는 사항(청구범위)

**작성 전 `{SHARED_SKILL_ROOT}/reference/claim-drafting.md`를 반드시 Read**하여 아래 독트린 적용.

- **제1원칙**: 독립항 = 신규성 지탱 최소 결합(novelty-bearing minimal combination). 신규성 지탱 요소 전부 포함·그 외 배제, 길이는 결합 크기가 결정.
- **구조**: 전제부/전이부("~을 포함하는" 개방형)/특징부. **서술 순서**: 구성요소 → 연결관계 → 기능·작용.
- **antecedent basis**: "상기 X"는 선행 기재 후 사용(작성 시점 준수).
- **상위개념화 사다리**: 구체 용어 → 기능적 표현, 각 단계 §6 실시예 뒷받침.
- **수치·재료 한정은 종속항 이동**(신규성 필수 예외만 독립항).
- **종속항 트리 4~6 fallback** + claim differentiation. 회피설계·`rejection_combinations` 방어를 종속항 한정으로 봉쇄.
- **회피설계 차단 (사업화, 2026-07-10 — claim-drafting.md §11)**: 각 독립항마다 경쟁사 회피 시나리오(치환·생략·공정변경·공급망 분리·실시주체 분산, E1~E5) 최소 2개 상정 → 상위개념 문언·병렬 독립항·봉쇄 종속항으로 차단. 치환 후보는 §6 변형 실시예로 뒷받침. 결과는 부록 B.4 매트릭스로 기록.
- **침해 검출성 (사업화, 2026-07-10 — claim-drafting.md §12)**: 전 청구항에 검출성 등급(A: 제품 관찰 / B: 리버스엔지니어링 / C: 내부 정보 필요) 부여, **최소 1개 독립항은 등급 A/B**. 방법 발명은 공정 지문(제품에 남는 구조 흔적)을 물건항/물성 한정으로 병행 청구. 결과는 부록 B.5 테이블로 기록.
- **부호 병기**("챔버(10)") — §6·도면·§9 부호설명 동기화.
- **카테고리**: 물건+방법 병행 필수, 가능 시 소자 추가. 센서·제어부·연동 요소(아이트래킹·캘리브레이션 등)가 있으면 **시스템 독립항(장치+센서+제어부)** 추가 검토 — 최대 4축(방법+장치+소자+시스템). 실질 발명사상이 지지할 때만(지표용 카테고리 부풀리기 금지). 발명 단일성 확인.

### 요약서(초록) — §9 앞 별도 블록 `## 요약서`
§1(명칭)+§5(목적)+§6(핵심 구성)을 종합하여 **400자 내외** 개조식 요약서를 §9 바로 앞 `## 요약서` 헤더로 생성. 과제·핵심 구성·주요 효과를 압축.

### §9 추가자료
도면 목록, 설계 파라미터 테이블, 참고문헌 목록([N] 형식).
- **도면부호 목록 테이블 (필수, 2026-07-06)**: `| 부호 | 명칭 | 관련 도면/청구항 |` — §6·§8 부호 병기와 동기화. 도면 PNG에 부호 미표기 시 "출원용 정식 도면 작성 시 반영" 부기.
- **파급/사업화 블록 (필수, 2026-07-06 — SMART5/KPAS 활용성·시장성 레버)**: 적용 시장·제품 / 후속출원(분할·연속) 구조 / PCT·삼극 패밀리 플랜(계획 서술만). 실질 내용이 있을 때만 채움 — 자동등급 지표용 빈 문구·과장 금지(자동점수 ≠ 실제 권리강도).

## section_summary 출력 (patent-incubation 추가)

MD 파일의 YAML 프론트매터에 `section_summary`를 추가한다:

```yaml
---
title: "발명명칭"
created: YYYY-MM-DD
inventor: "발명자"
field: "기술분야"
tags: [발명내용설명서, KIMM]
section_summary:
  s1: {chars: 15, summary: "발명 명칭"}
  s2: {chars: 20, summary: "논문발표 여부"}
  s3: {chars: 500, summary: "배경 요약 1-2문장"}
  s4: {chars: 800, summary: "종래기술 문제점 요약 1-2문장"}
  s5: {chars: 200, summary: "목적 요약 1문장"}
  s6: {chars: 2000, summary: "구성 요약 — 포함 IFR, 핵심 구성요소, 실시예 수"}
  s7: {chars: 400, summary: "효과 요약 1-2문장"}
  s8: {chars: 600, summary: "독립항 N개, 종속항 M개, 주요 독립항 1줄 요약"}
  s9: {chars: 300, summary: "도면 N개, 참고문헌 M건"}
  abstract: {chars: 400, summary: "요약서(초록) — 과제·핵심 구성·주요 효과 압축"}
---
```

Gate 6에서 사용자에게 섹션별 요약을 표시하는 데 사용된다.

## 출력 검증

- `## §1` ~ `## §9` 헤더 9개 존재 확인
- `## 요약서` 블록(400자 내외)이 §9 앞에 존재 확인
- `## 부록 A` ~ `## 부록 C` 헤더 3개 존재 확인
- 각 섹션 본문 비어있지 않음
- A.4.1 IFR 설명 테이블 + A.4.2 IFR 정량 평가 테이블 존재
- section_summary YAML 필드 존재
- 누락 시 1회 재생성 시도
