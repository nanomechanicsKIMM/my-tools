# Phase 6: 발명내용설명서 최종 작성

## 입력

`invention_manifest.json`에서 각 Phase 출력 파일 경로를 읽어 로드:
1. `input` — 원본 사용자 입력 (field, problem, idea, inventor, references)
2. `triz_system.json` — 시스템 분석 (Phase 1)
3. `triz_analysis.json` — 모순 + IFR 목록 (Phase 2)
4. `evaluation.json` — 정량 평가 + 순위 (Phase 4)
5. `prior_art.json` — 선행특허 분석 (Phase 5, 없으면 degraded 처리)
6. `templates/disclosure-report.md` — MD 템플릿
7. `reference/user-philosophy.md` — 발명자 철학 및 선호 사항

추가로, 원본 사용자 입력 문서(MD 파일)도 읽어 참조 문헌(References 섹션)을 추출한다.

## 작업

### 핵심 원칙

- **9개 섹션 모두 채움** (빈 섹션 불가)
- **부록 3개(A/B/C) 모두 채움** — 분석 내용 누락 방지
- **선행특허 기반 순위 재조정**: Phase 4 평가 점수에 novelty(신규성) 관점 반영
- **기계 파싱 가능**: 각 섹션은 `## §N` 헤더로 구분 (Phase 7 HWPX 변환용)
- **한국어 작성**: 발명내용설명서는 한국어로 작성
- **발명자 철학 반영**: `user-philosophy.md`의 핵심 원칙과 스타일 선호를 문서 전반에 반영
- **참고 문헌 출처 명시**: 모든 인용에 출처(논문 DOI, 특허번호, URL)를 표기

### TRIZ 용어 사용 규칙 (필수)

TRIZ는 아이디어 도출 수단이다. 발명내용설명서 MD 내에서 두 영역을 구분한다:

| 영역 | TRIZ 용어 사용 | 설명 |
|------|---------------|------|
| **§1~§9 본문** | **금지** | 일반적인 기술 용어로만 서술. "기술적 모순 TC1" → "점진적 접촉과 변형 방지의 상충 관계" 등으로 변환 |
| **부록 A (TRIZ 분석 상세)** | **허용** | 모순 ID, IFR 번호, TRIZ 원리 번호 등 상세 기록 |

§1~§9에서 **절대 사용하지 않는 용어**:
- TRIZ, 모순 매트릭스, 기술적 모순(TC), 물리적 모순(PC)
- IFR (Ideal Final Result), 이상적 최종 결과
- TRIZ 발명 원리 번호 (원리 1, 원리 35 등)
- 분리 법칙 (시간 분리, 공간 분리, 조건 분리 등의 TRIZ 용어)
- 39가지 파라미터 명칭을 TRIZ 번호와 함께 사용하는 것

§1~§9에서 **대신 사용하는 표현**:
- "상충하는 요구사항", "기술적 딜레마", "양립하기 어려운 조건"
- "본 발명에서 제안하는 해결 방안", "핵심 구성"
- 구체적인 기술적 설명 (물리적 메커니즘, 재료 특성, 공정 조건 등)

### 전 섹션 공통 작성 규칙 (절대 원칙)

#### 1. 개조식 문장 형태 (필수)

발명내용설명서의 **모든 문장**(§1 제외)은 "개조식(개조 문체)" 형태로 작성한다.

- 종결 어미: `~함.`, `~있음.`, `~필요함.`, `~없음.`, `~임.`, `~됨.` 등으로 끝낸다.
- **서술형 평서체(`~이다`, `~한다`, `~였다`) 금지**
- 그러나 짧게 끊지 말고, **한 문장 안에 상세한 기술적 설명·조건·수치·인과·예시를 충분히 포함**한다. "상세한 설명이 추가된 개조식"이 핵심.

| 좋은 예 (✓) | 나쁜 예 (✗) |
|------------|-----------|
| `355 nm UV 레이저를 ns 단위 펄스폭으로 조사하여 GaN 에피층만 선택적으로 박리함으로써 샤파이어 기판의 손상 없이 LED를 분리할 수 있음.` | `UV 레이저를 사용한다.` (지나치게 축약) |
| `롤 스탬프는 점착력이 온도에 따라 가변되는 PDMS/Kapton 이중층으로 구성되며, 전사 단계에서는 점착력을 극대화하고 박리 단계에서는 최소화하는 방식으로 동일 장비 내 이중 기능을 구현함.` | `롤 스탬프는 PDMS로 만든다.` (상세 설명 부족, 평서체) |
| `본 발명은 피치 가변성이 요구되는 Micro-LED 공정에서 종래 인터포저 단계를 생략하여 제조비용 약 30% 절감이 가능함.` | `인터포저 단계를 생략한다.` (원인·효과 미포함) |

#### 2. 계층적 글머리기호 (§3 이후 권장, §6 필수)

하위 섹션 번호(`6.1`, `6.1.1`) 대신 **markdown 계층 글머리기호**를 사용한다. HWPX 변환 시 자동으로 계층 bullet(●/○/▪/-)과 들여쓰기로 렌더링된다.

- 1 레벨 들여쓰기 = 공백 2칸
- 기호: `-` (또는 `*`) 사용
- 글머리기호 다음의 연속 문단(bullet 없는 줄)은 **해당 bullet과 같은 레벨**로 자동 정렬됨 → 본문이 글머리기호 위치 아래 깔끔히 정렬됨

**좋은 작성 예 (§6)**:

```markdown
- 전체 시스템: 본 발명은 레이저 재배열부와 롤 전사부를 하나의 챔버에 통합한 장비로 구성됨.
  해당 통합 구조는 공정 간 이송 손실을 제거하고 정렬 오차를 20 μm 이하로 유지함이 필요함.
  - 레이저 재배열부: 투명 스테이지 하부에서 선택적으로 UV 레이저를 조사하여 특정 피치의 LED만 분리함.
    - 파장 설정: GaN 에피층에 대한 선택적 흡수를 위해 355 nm UV 레이저를 적용함.
    - 펄스 제어: 샤파이어 기판 손상 방지를 위해 5 ns 이하 펄스폭으로 설정함이 필요함.
  - 롤 전사부: 점착력이 약화된 LED를 PDMS 롤로 픽업 후 타겟 기판에 상온 전사함.
```

**금지 예시 (❌ 숫자 하위섹션)**:

```markdown
### 6.1 전체 시스템 구성
본 발명은 …
### 6.2 핵심 구성요소
…
```

#### 3. 혼용 금지

- §1(발명 명칭), §2(해당 없음 등)은 짧은 문장이 허용된다.
- 그 외 모든 섹션은 개조식 + (§6은) 계층 글머리기호 형식을 지킨다.

### Claim-First 작성 순서 (필수)

**§8 청구범위 작성 전 `{SKILL_ROOT}/reference/claim-drafting.md`를 반드시 Read**하여 독트린을 적용한다.

§6 상세 서술 전에 청구항 골격을 먼저 설계한다:

1. **(a) 필수 구성요소 최소집합 → 독립항 골격**: 신규성·진보성을 지탱하는 최소 결합(novelty-bearing minimal combination)을 도출하여 독립항 골격을 세운다.
2. **(b) IFR·회피 한정 → 종속항 트리**: 각 IFR·회피설계 한정요소를 단계적 fallback 종속항 트리(4~6 계층)로 배치한다. 골격 설계 시점에 경쟁사 회피 경로 5유형(E1~E5, claim-drafting.md §11)과 검출성 등급(A/B/C, §12)을 함께 상정한다.
3. **(c) §6이 청구항을 지지하도록 작성**: §6 본문의 모든 bullet은 어느 청구항 구성요소를 뒷받침(112a support)하는지 내부적으로 추적한다. 상위개념화 사다리의 각 단계는 반드시 §6 실시예로 뒷받침한다.

작성 실행 순서: [청구항 골격 선행 설계] → §6(청구항 전 구성요소 지지) → §8 확정 → 나머지 섹션.

### 섹션별 작성 가이드

#### §1 발명(고안)의 명칭
- 간결하고 기술적으로 정확한 명칭
- 20자 이내 권장

#### §2 논문발표/외부공개 여부
- **형식 기재가 아닌 실질 조사 결과로 서술**: `prior_art.json`의 `self_disclosure`(발명자 본인·KIMM 소속 저자의 논문·학회 발표·보도자료 조회 결과)를 반영한다.
- 발표 이력이 없으면(조사 결과 자기공개 미발견) "해당 없음" 기재
- 발표 이력이 있으면 학회명/저널명, 공개일, 논문 제목, DOI/URL 기재
- **자기공지 발견 시**: 공개일을 명시하고, **공지예외주장(신규성 의제, 공개일로부터 12개월 내 출원) 기한·요건 경고**를 §2와 최종 보고에 표시한다. source_files로 입력된 발명자 자신의 논문도 자기공지 후보로 검사한다.

#### §3 발명(고안)의 배경(동기)
- 기술 분야의 현황과 동향
- **Phase 1 반영**: 상위 시스템, 하위 시스템 정보로 기술적 맥락 설명
- **선행특허 반영**: 관련 선행특허에서 파악된 기술 동향 포함
- **참고 문헌 인용**: 사용자 제공 참조 문헌의 핵심 내용을 인용 (저자, 연도, 제목, DOI/URL)
- 해결이 필요한 문제의 배경 설명
- 3-5개 단락

#### §4 종래기술 및 문제점
- 기존 기술의 구체적 설명
- **Phase 2 반영**: 도출된 기술적/물리적 모순을 명시적으로 기술
  - 기술적 모순: "개선 파라미터(X)를 향상시키면 악화 파라미터(Y)가 저하되는 모순"
  - 물리적 모순: "A 성질이 동시에 필요하면서도 ~A 성질도 필요한 모순"
- **선행특허 인용**: 유사도 상위 특허 중 관련성 높은 것을 인용 (특허번호, 출원인, 핵심 내용)
- **참고 문헌 인용**: 종래 기술 논문/특허의 구체적 한계를 출처와 함께 기술
- **진보성 논증 골격 (Problem-Solution)**: 객관적 기술 과제 → 최근접 선행기술 → 해결수단 비자명성 구조로 서술하고, 진보성 3논거를 명시적으로 배치한다:
  - **결합 곤란성**: 선행문헌 간 결합에 동기 부재 또는 기술적 장애 존재
  - **Teaching away**: 선행기술이 본 발명 방향을 회피·부정하는 기재 (§4에서 종래기술 한계로 서술)
  - (상승효과는 §7에서 정량 서술)
- 종래기술의 한계와 문제점을 체계적으로 정리
- 3-5개 단락

#### §5 발명(고안)의 목적
- TRIZ 분석에서 도출된 핵심 모순을 해결하는 것이 목적
- 구체적이고 측정 가능한 목적 서술
- 1-2개 단락

#### §6 발명(고안)의 구성
- **Phase 4 상위 IFR 기반** 구체적 구성 설명
- **Phase 5 신규성 분석 반영**: 선행특허 미개시 IFR을 중심으로 서술
- **TRIZ 원리 반영**: 각 구성요소에 적용된 TRIZ 발명 원리 번호를 서술에 포함
- **발명자 철학 반영**: user-philosophy.md의 핵심 원칙(에너지 효율성, 구조적 단순화 등) 관점에서 서술
- **형식 — 계층적 글머리기호 필수** (숫자 하위섹션 `6.1/6.2/...` 금지):
  - 레벨 0 (`- `): 최상위 주제 — 전체 시스템 / 핵심 구성요소 / 작동 원리 / 실시예 / 변형 실시예
  - 레벨 1 (`  - `): 주제별 세부 구성요소
  - 레벨 2 (`    - `): 파라미터·재료·공정 조건 등 상세 항목
  - 레벨 3 (`      - `): 더 세부적인 수치·변형안
- **각 글머리기호는 개조식(`~함.`, `~필요함.`, `~있음.`)으로 끝나되 기술적 메커니즘·수치·조건·인과 관계를 상세히 포함**한다.
- 구성요소 아래에 일반 문단으로 부연 설명을 넣으면 같은 레벨로 자동 정렬된다 (글머리기호 위치에 맞춘 hanging indent).
- 가장 상세한 섹션, 토큰 예산의 30%+ 할당 — 최소 15~30개 글머리기호 노드 권장

#### §7 발명(고안)의 효과
- §6의 구성으로 달성되는 기술적 효과
- **Phase 2 모순 해결 확인**: 기술적/물리적 모순이 어떻게 해결되었는지 TRIZ 관점에서 설명
- 종래기술(§4) 대비 개선 효과 정량/정성 서술
- **진보성 3논거 중 상승효과 서술**: 결합 시 개별 효과의 단순 합을 초과하는 시너지를 **정량 수치와 함께** 명시한다(§4의 결합곤란성·teaching away와 함께 3논거 완성).
- **rejection_combinations 반영**: Phase 5 `rejection_combinations`의 방어 논거(defense)를 효과 서술에 연결하고, 해당 방어를 §8 종속항 설계에도 반영한다.
- 에너지 효율성, 공정 단순화, 품질 향상, 비용 절감 등 다면적 효과
- 2-4개 단락

#### §8 보호받고자 하는 사항(청구범위)

**작성 전 `{SKILL_ROOT}/reference/claim-drafting.md`를 반드시 Read**하여 아래 독트린을 적용한다.

- **제1원칙**: 독립항 = 신규성·진보성을 지탱하는 최소 구성의 결합(novelty-bearing minimal combination). 신규성 지탱 요소는 전부 포함, 그 외는 배제. 길이는 결합 크기가 결정(글자수 최적화 대상 아님).
- **구조**: 전제부(공지 부분) / 전이부("~을 포함하는" 개방형 기본) / 특징부(신규 구성).
- **서술 순서**: 구성요소 열거 → 연결관계 → 기능·작용 한정.
- **선행어 규칙(antecedent basis)**: "상기 X"는 선행 기재 후에만 사용 — 작성 시점에 준수.
- **상위개념화 사다리**: 구체 용어 → 상위개념/기능적 표현(예 "SMA 스프링" → "형상기억 복원수단"). 각 단계는 §6 실시예로 뒷받침. 신규성 경계 직전까지만 끌어올림.
- **수치·재료 한정은 종속항으로 이동** (신규성 지탱 필수 예외만 독립항 잔류).
- **종속항 트리**: 단계적 fallback 4~6 계층. 각 종속항은 상위 청구항 대비 실질적으로 다른 한정 추가(claim differentiation). 무의미한 청구항 수 부풀리기 금지.
- **회피설계 봉쇄**: Phase 5 선행특허·`rejection_combinations`의 방어 논거를 종속항 한정으로 반영.
- **회피설계 차단 (사업화, 2026-07-10 — claim-drafting.md §11)**: 각 독립항마다 경쟁사 회피 시나리오(치환·생략·공정변경·공급망 분리·실시주체 분산, E1~E5) 최소 2개를 상정하고, 상위개념 문언·병렬 독립항·봉쇄 종속항으로 차단한다. 치환 후보는 §6 변형 실시예로 뒷받침. 결과를 부록 B.4 회피설계 차단 매트릭스로 기록.
- **침해 검출성 (사업화, 2026-07-10 — claim-drafting.md §12)**: 모든 청구항에 검출성 등급(A: 제품 관찰 / B: 리버스엔지니어링 / C: 내부 정보 필요)을 부여하고 **최소 1개 독립항은 등급 A/B**로 작성. 방법 발명은 공정이 제품에 남기는 구조적 지문(계면 형상·잔류응력·결정 배향·조성 구배 등)을 물건항/물성 한정으로 병행 청구. 결과를 부록 B.5 침해 검출성 테이블로 기록.
- **부호 미병기 (2026-07-13 개정)**: 청구항·본문에서 구성요소는 이름으로만 지칭한다 — 도면 부호 괄호 병기("챔버(10)") 금지. 출원용 정식 도면·부호 체계는 변리사가 별도 작성하므로 내부 번호가 오해를 유발할 수 있다. 구별이 필요하면 서수·수식어("제1 롤", "하부 기판")를 사용한다.
- **카테고리**: 물건(장치) + 방법 독립항 병행 필수, 가능 시 소자 독립항 추가. **발명에 센서·제어부·연동 요소(아이트래킹·캘리브레이션·피드백 제어 등)가 있으면 시스템 독립항(장치+센서+제어부 결합)을 추가 검토**하여 최대 4축(방법+장치+소자+시스템) 포트폴리오 구성 — 단 실질 발명사상이 지지할 때만(지표용 카테고리 부풀리기 금지). 복수 독립항의 발명 단일성 확인, 위반 우려 시 분할출원 전략 부기.

#### 요약서(초록) — §9 앞 별도 블록 `## 요약서`
- 출원 서류 세트(명세서·청구범위·요약서·도면) 중 요약서를 자동 생성한다.
- **§1(명칭) + §5(목적) + §6(핵심 구성)**을 종합하여 **400자 내외**로 작성한다.
- 발명이 해결하는 과제, 핵심 구성, 주요 효과를 압축적으로 담되 개조식으로 종결한다.
- `## 요약서` 헤더로 §9 바로 앞에 배치한다.

#### §9 추가자료
- 도면 목록 (Phase 6b에서 생성될 도면 참조) — 각 도면은 **내용 기반 제목만** 기재
- **도면 번호·부호 미기재 (2026-07-13 개정)**: "[도 N]" 번호 부여·번호별 설명 목록("도 1은 ~")·도면부호 목록 테이블을 작성하지 않는다. 출원용 정식 도면·부호 체계는 변리사가 별도 작성하므로 내부 번호가 오해를 유발할 수 있다(claim-drafting.md §7).
- 설계 파라미터 테이블 (온도 범위, 압력 범위, 재료 종류 등)
- 적용 가능한 소자/제품 예시
- **파급/사업화 블록 (필수, 2026-07-06 신설 — SMART5/KPAS 활용성·시장성 레버)**:
  - **적용 시장·제품**: 발명이 적용될 산업·제품군을 구체적으로 서술 (KPAS 시장성 축 직접 반영)
  - **후속출원 구조**: 분할·연속출원 후보(특정 종속항 계열의 별도 패밀리화 등)를 명시 — 피인용(forward citation) 구조의 사전 설계
  - **패밀리 플랜**: PCT/삼극(US·JP·EP) 출원 계획 여부와 근거 시장을 명시 (계획 서술만 — 실제 출원은 별도 의사결정)
  - 안티게이밍 원칙: 이 블록은 **실질 내용이 있을 때만** 채운다. 자동등급(SMART5/KPAS) 지표를 위한 빈 문구·과장 서술은 금지 — 자동점수 ≠ 실제 권리강도.
- **참고문헌 목록** (§9 마지막에 배치)

### 참고문헌 인용 규칙 (§1~§9 전체 적용)

§3(배경), §4(종래기술) 등에서 선행 연구/특허를 인용할 때 **번호 인용 형식 [N]**을 사용한다.
§9 마지막에 참고문헌 목록을 번호 순서대로 기재한다.

**본문 인용 예시:**
- "진공 환경에서 그래핀을 전사하는 방법이 제안되었다 [1]."
- "기존 특허 [2]에서는 열처리 모듈을 이용한 전사 시스템을 개시하였다."

**§9 참고문헌 목록 형식:**

```
참고문헌

[1] 저자명, "논문/특허 제목", 학술지/특허번호, 연도. DOI 또는 URL
[2] 저자명, "논문/특허 제목", 학술지/특허번호, 연도. DOI 또는 URL
...
```

**참고문헌 수집 대상:**
1. 사용자 입력 문서의 References 섹션에 기재된 논문/특허
2. Phase 5 선행특허 조사에서 인용한 특허 (특허번호, 출원인, 제목)
3. §3~§4 작성 시 인용한 기술 문헌

**주의:** 참고문헌 번호는 §1~§9 본문에서 처음 등장하는 순서대로 부여한다.

### 부록 작성 가이드 (누락 금지)

#### 부록 A: TRIZ 분석 상세
- **A.1 시스템 분석**: Phase 1의 주 기능, 상위/하위 시스템을 테이블로 정리
- **A.2 기술적 모순**: Phase 2의 모든 기술적 모순을 테이블로 정리 (ID, 개선 파라미터, 악화 파라미터, 권장 원리)
- **A.3 물리적 모순**: Phase 2의 모든 물리적 모순을 테이블로 정리 (ID, 모순 내용, 분리 법칙, 적용 원리)
- **A.4 IFR 전체 목록 및 평가** — 반드시 2단계 구성:
  - **A.4.1 IFR 설명 테이블** (정량 평가 이전에 배치):
    - 모든 IFR을 주제별 그룹으로 분류 (예: SMA 메커니즘, Carrier 필름, 공정 제어, 장비 통합 등)
    - 각 IFR의 지향 방향, 해결 모순, 핵심 내용, 기술적 효과, 적용 원리를 테이블로 정리
    - 컬럼: IFR#, 지향 방향, 해결 모순(TC/PC ID), 핵심 내용, 기술적 효과, 적용 원리
    - 모순 → 원리 적용 → IFR → 기술적 효과의 논리적 체인이 명확히 드러나야 함
  - **A.4.2 IFR 정량 평가 테이블** (A.4.1 이후에 배치):
    - Phase 4 평가 점수 기반 순위 테이블 (순위, IFR#, 종합점수, 기술효과, 실현가능성, 비용효율, 특허성, 산업가치, 핵심 내용)

#### 부록 B: 선행특허 분석 요약
- **B.1 검색 조건**: 검색 DB, 키워드, 일자, 총 건수
- **B.2 주요 선행특허**: Phase 5의 분석 특허를 테이블로 정리 (특허번호, 출원인, 공개일, 핵심 내용, 유사도, 위험 수준)
- **B.3 차별성 분석**: 본 발명과 선행특허의 차별점을 서술
- **B.4 회피설계 차단 매트릭스 (필수, 2026-07-10 신설 — claim-drafting.md §11)**: `| 독립항 | 회피 시나리오 | 유형(E1~E5) | 차단 청구항 | 잔여 리스크 |` — 각 독립항마다 회피 시나리오 최소 2개. 잔여 리스크는 §9 사업화 블록의 후속출원 후보와 연결
- **B.5 침해 검출성 테이블 (필수, 2026-07-10 신설 — claim-drafting.md §12)**: `| 청구항 | 등급(A/B/C) | 입증 수단 | 비고 |` — 전 청구항 등급 부여, 등급 A/B 독립항 존재 확인, 방법항의 공정 지문 물건항 병행 여부 부기

#### 부록 C: 참고 문헌
- **C.1 사용자 제공 참고 문헌**: 사용자 입력 문서의 References 섹션에서 추출한 문헌 목록 (저자, 연도, 제목, DOI/URL)
- **C.2 선행특허 출처**: Phase 5에서 분석한 특허 목록 (특허번호, 출원인, 제목, URL)
- **C.3 TRIZ 참고 자료**: TRIZ 모순 매트릭스, 40가지 발명 원리, 4가지 분리 법칙

### 선행특허 기반 순위 재조정

- **`evaluation.json`의 `patentability_recheck`가 있으면 이를 우선 반영**(Phase 5.5 재채점 결과가 Phase 4 원점수보다 우선).
- Phase 4의 종합점수에 선행특허 분석 결과를 반영:

### 파일명 규칙

MD 파일명은 HWPX와 동일한 명명 규칙을 따른다:
- **초판**: `(YYYYMMDD 발명자) 발명명칭v1.md`
- **수정판**: `(YYYYMMDD 발명자) 발명명칭v2.md`, `v3.md`, ...
- 예시: `(20260331 김재현) 나노박막의 진공 대면적 전사 방법 및 장비v1.md`

버전 번호 결정 로직:
1. output_dir에서 동일 발명명칭의 기존 MD 파일을 검색
2. 기존 파일이 없으면 v1
3. 기존 파일이 있으면 가장 높은 버전 번호 + 1

### 출력 파일 목록

1. `(YYYYMMDD 발명자) 발명명칭vN.md` — Obsidian 호환 MD 파일 (9개 섹션 + 부록 3개)
2. `reference/user-philosophy.md` 업데이트 — §4에 새 패턴 추가
3. manifest 업데이트: `"phase6": {"status": "completed", "output": "(YYYYMMDD 발명자) 발명명칭vN.md"}`

### 출력 검증

생성된 MD 파일에서:
- 파일명이 `(YYYYMMDD 발명자) 발명명칭vN.md` 형식인지 확인
- `## §1` ~ `## §9` 헤더가 모두 존재하는지 확인
- `## 요약서` 블록(400자 내외)이 §9 앞에 존재하는지 확인
- `## 부록 A` ~ `## 부록 C` 헤더가 모두 존재하는지 확인
- 각 섹션 본문이 비어있지 않은지 확인
- 부록 A의 IFR 수가 Phase 2의 IFR 수와 일치하는지 확인
- 부록 C에 사용자 참고 문헌이 1건 이상 포함되었는지 확인
- 섹션/부록 누락 시 1회 재생성 시도

## 주의사항

- 선행특허가 degraded 상태면 §3/§4/§8에 `[선행특허 수동 보완 필요]` 표시, 부록 B에도 degraded 안내
