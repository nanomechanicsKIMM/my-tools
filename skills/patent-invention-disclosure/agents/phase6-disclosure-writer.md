# Phase 6: 발명내용설명서 최종 작성

## 입력

`invention_manifest.json`에서 각 Phase 출력 파일 경로를 읽어 로드:
1. `input` — 원본 사용자 입력
2. `triz_system.json` — 시스템 분석
3. `triz_analysis.json` — 모순 + IFR 목록
4. `evaluation.json` — 정량 평가 + 순위
5. `prior_art.json` — 선행특허 분석 (없으면 degraded 처리)
6. `templates/disclosure-report.md` — MD 템플릿

## 작업

### 핵심 원칙

- **9개 섹션 모두 채움** (빈 섹션 불가)
- **선행특허 기반 순위 재조정**: Phase 4 평가 점수에 novelty(신규성) 관점 반영
- **기계 파싱 가능**: 각 섹션은 `## §N` 헤더로 구분 (Phase 7 HWPX 변환용)
- **한국어 작성**: 발명내용설명서는 한국어로 작성

### 섹션별 작성 가이드

#### §1 발명(고안)의 명칭
- 간결하고 기술적으로 정확한 명칭
- 20자 이내 권장

#### §2 논문발표/외부공개 여부
- 발표 이력이 없으면 "해당 없음" 기재
- 발표 이력이 있으면 학회명, 일자, 논문 제목 기재

#### §3 발명(고안)의 배경(동기)
- 기술 분야의 현황과 동향
- **선행특허 반영**: 관련 선행특허에서 파악된 기술 동향 포함
- 해결이 필요한 문제의 배경 설명
- 3-5개 단락

#### §4 종래기술 및 문제점
- 기존 기술의 구체적 설명
- **선행특허 인용**: 유사도 상위 특허 중 관련성 높은 것 인용
- 종래기술의 한계와 문제점 명시
- 본 발명과의 차별점 암시
- 3-5개 단락

#### §5 발명(고안)의 목적
- TRIZ 분석에서 도출된 핵심 모순을 해결하는 것이 목적
- 구체적이고 측정 가능한 목적 서술
- 1-2개 단락

#### §6 발명(고안)의 구성
- 상위 IFR을 기반으로 발명의 구체적 구성 설명
- 구성요소 간 관계와 작동 원리
- 실시예 포함 (가능한 경우)
- 5-8개 단락 (가장 상세한 섹션)

#### §7 발명(고안)의 효과
- §6의 구성으로 달성되는 기술적 효과
- 종래기술 대비 개선 효과 정량/정성 서술
- TRIZ 분석의 모순 해결 결과 반영
- 2-4개 단락

#### §8 보호받고자 하는 사항(청구범위)
- 독립항 1개 + 종속항 2-3개 형태
- **회피설계 고려**: 선행특허 대비 차별화된 청구범위
- 권리 범위가 넓되 선행특허에 저촉되지 않도록 조정
- 3-5개 항

#### §9 추가자료
- 도면 설명 (텍스트로 기술)
- 실험 데이터 또는 시뮬레이션 결과 (있는 경우)
- "별도 도면 첨부 예정" 등 안내

### 선행특허 기반 순위 재조정

Phase 4의 종합점수에 선행특허 분석 결과를 반영:
- 유사 선행특허가 많은 IFR → 신규성 낮음 → 순위 하향
- 회피설계 가능성이 높은 IFR → 특허성 양호 → 순위 유지/상향
- 최종 순위 기준으로 §6(구성)의 주 발명 선정

## 출력

1. `disclosure.md` — Obsidian 호환 MD 파일 (9개 섹션)
2. manifest 업데이트: `"phase6": {"status": "completed", "output": "disclosure.md"}`

### 출력 검증

생성된 MD 파일에서:
- `## §1` ~ `## §9` 헤더가 모두 존재하는지 확인
- 각 섹션 본문이 비어있지 않은지 확인
- 섹션 누락 시 1회 재생성 시도

## 주의사항

- 선행특허가 degraded 상태면 §3/§4/§8에 `[선행특허 수동 보완 필요]` 표시
- §6(구성)이 가장 중요하고 상세해야 함 — 토큰 예산의 30%+ 할당
- 청구범위(§8)는 법적 문서이므로 정확한 표현 사용
