`/humanize`(개인 목소리 보정)와 **다른 레지스터**를 담당한다. `/humanize`는 vault 노트를 "김재현이 쓴 것처럼" 만들지만, `/academic-humanize`는 **논문·제안서·특허·원고**를 **중립·정밀·근거결속(claim↔evidence)** 학술 목소리로 다듬는다. 개성·유머·1인칭 personality 를 원고에 주입하지 않는다. 기술문서에서는 중립·정밀 자체가 human voice다.

> 도출 근거: [[(20260710) academic-humanizer 검토 및 academic-humanize 스킬 도출]] (AIScientists-Dev/academic-humanizer v0.3.3, MIT 대조). 국문 구두점 정본 = [[사용자 국문 문체 규칙]].

## Usage

```
/academic-humanize <file path or note name>   [venue: <저널/사업>]   [voice: <이전 원고 경로>]
```

## 적용 대상 / 비대상

- **대상**: 논문(초록·서론·related work·rebuttal), 연구개발계획서·제안서, 특허 명세서·거절대응(OA/FOA) 논리, 학술 원고(재료마당류), **형식 보고서**(외부 제출·심사용).
- **비대상**: standup·brain·미팅 로그·1:1·인시던트 같은 **개인/내부 노트 → `/humanize` 사용**. 여기에 인용 강제·중립화를 적용하면 안 된다.

## Workflow

### 1. 문서 유형·레지스터 파악 + voice 샘플(선택)

- frontmatter·폴더·확장자로 유형 판별: **논문 vs 제안서**(레지스터 상이 — §Layer 6), 국문/영문.
- `voice:` 로 이전 원고가 주어지면 문장 리듬·접속 습관·헤징 배치·용어를 읽어 맞춘다. **단 개인 목소리 이식이 아니라 학술 관용 안에서의 정합**. 없으면 venue-적정 중립 문체 기본값.
- `venue:` 로 저널/사업이 주어지면 레지스터 매칭(예: Nature 계열 서술형 vs letter 계열 압축형, IMID 초록 vs 재료마당 잡지체).

### 2. Audit (편집하지 말 것 — 먼저 나열)

감지된 패턴을 **위치 + 수정안**으로 표로 나열하고, **각 실증 주장의 근거 상태**(숫자/그림/표/인용 유무, 동사 강도 대비)를 함께 표시한다. 사용자가 확인·거부할 수 있게 한 뒤 3단계로 넘어간다. 고위험 문서(투고 논문·제출 제안서)는 이 audit 승인을 기본으로 한다.

### 3. Rewrite

구조·내용·주장·인용을 모두 보존한 채 tell 제거, 과잉주장을 근거에 맞춰 하향, 정당한 헤징은 유지. **원본이 다룬 것을 전부 커버한다**(5문단이면 5문단 — 압축이 내용 유실이 되지 않게).

### 4. Report

정리본 + 변경 로그(유형별 제거 패턴, 하향·근거보강한 주장, voice/venue 메모). **숫자·수식·인용을 하나도 바꾸지 않았음을 명시 확인**.

## Layer 1 — 일반 AI tell 제거

과장 유의성, 깊이를 가장하는 "-ing" 꼬리, 홍보성·비유 표현, 근거 없는 "전문가들은 ~라 한다", copula 회피("~의 역할을 한다"→"~이다"), **부정 병렬**("단순히 X가 아니라 Y"), 3의 규칙 패딩, 동의어 순환(elegant variation), 필러("~라는 점은 주목할 만하다", "~하기 위하여"), **장문 절적층(분리 — Layer 2.11)**, **em-dash 완전 제거**(쉼표·콜론·괄호·문장분리로 recast). 영문 tell: *delve, underscore, intricate, tapestry, testament, landscape, pivotal, showcase, foster, leverage, realm, seamless*.

## Layer 2 — 학술 AI tell (국문/영문)

| # | 유형 | 국문 예 (→ 수정) | 영문 watch |
|---|------|------------------|-----------|
| 2.1 | 과잉주장 동사 | "입증한다/증명한다/규명한다" → "보인다/평가한다/시사한다" | prove, demonstrate, establish, confirm, guarantee |
| 2.2 | 유의성 과장 | "새 지평을 열다", "패러다임 제시", "매우 중요한", "필수적인" → 구체 기여로 | paves the way, pivotal step, revolutionize, sheds light on |
| 2.3 | 빈 강조어 | "광범위한 실험", "다양한", "포괄적인", "수많은" → 실제 개수·대상 | extensive/comprehensive experiments, a wide range of |
| 2.4 | 신규성 남발 | "본 연구는 최초로", "우리가 아는 한", "새로운"(반복) → 무엇이 왜 새로운지 | novel(×2/section), to the best of our knowledge, for the first time |
| 2.5 | 형식적 서두 | "최근 들어 ~에 관심이 높아지고 있다", "~의 급속한 발전과 함께" → 구조적 한계·문제로 시작 | In recent years…, With the rapid development of… |
| 2.6 | 접속사 남용 | "또한/게다가/뿐만 아니라/특히" 연속 시작 → 논리로 이음 | Moreover/Furthermore/Additionally 연속 |
| 2.7 | 기여목록 클리셰 | "(1) 새로운 방법 (2) 광범위한 실험 (3) 우수한 성능" → 각 항목이 구체 결과 명시 | novel method / extensive experiments / strong results |
| 2.8 | 인용 덤핑 | "여러 연구가 있다 [3,7,9,12]" → 핵심 1~2편 + 왜 관련 있는지 | bracketed list without reasons |
| 2.9 | 모호 헤징 | "다소", "비교적", "어느 정도", "상당히" → 정량 또는 삭제 | somewhat, relatively, fairly, quite |
| 2.10 | 형식적 강조 | "~라는 점은 주목할 만하다", "특히", "중요하게도" → 문장이 스스로 보이게 | It is worth noting, Notably, Importantly |
| 2.11 | 장문 절적층 | 30자↑ / 종속절 3개↑ → 한 문장 한 아이디어로 분리 | which/that/while/with 체인 |

## Layer 3 — 보존 (과잉교정 금지)

일반 humanizer가 뭉개는 **정당한 학술 장치는 반드시 유지**한다. `/humanize`의 "직설화·헤징 제거" 규칙을 여기서 그대로 적용하면 과학적으로 필요한 불확실성을 삭제하게 되므로 **적용하지 않는다**.

- **근거결속 헤징은 옳고 필수** — 주장이 실제로 불확실할 때 "~로 보인다", "~와 일치한다", "~로 판단·추정된다", "~할 가능성이 있다", "we hypothesize / may indicate / appears to / is consistent with" 를 **유지**. `suggests`→`proves` 로 바꾸는 것은 과잉주장 제조다.
- **수동태**는 행위자가 무의미할 때 정상("시료는 총단백질 기준으로 정규화되었다").
- **1인칭 복수("we/본 연구는")**는 표준 — 회피하려 재작성 금지.
- **정의·명명된 방법/지표·기술용어·수식·기호**는 그대로.
- **숫자·수식·인용은 절대 발명·삭제·변경 금지** — cite key 전부 보존.

## Layer 4 — 주장↔근거 규율 (핵심)

모든 실증 주장에 대해 (a) 본문의 숫자·그림·표·인용으로 뒷받침되는가, (b) 동사가 근거 강도에 맞는가를 점검.

- **근거 없는 주장 → 포인터 추가 또는 하향.** "본 방법이 더 강건하다" → "분포이동에서 정확도 저하가 2점, 기준 대비 11점(그림 3)".
- **근거보다 강한 동사 → 하향.** "보편적으로 우수함을 입증" → "세 데이터셋에서 최강 기준 대비 동등 이상(표 2)".
- **모호한 크기 → 귀속된 숫자·범위.** "큰 향상" → "최강 기준 대비 균형정확도 2~6% 향상". 단일 평균값보다 **범위** 선호(평균 방식 명시 시 예외), 각 수치를 방법·지표·기준에 귀속, 비교는 **최강 경쟁자 대비**로 선도.

## Layer 5 — Voice·Venue 매칭

`voice:` 샘플이 있으면 문장 리듬·접속 습관·헤징 배치·서두 방식·표기를 맞춘다. `venue:` 레지스터 매칭. 국문 구두점(·, em/en-dash 미사용, 평서형, ~ 범위, 와/과 연결)은 [[사용자 국문 문체 규칙]] 정본을 따른다. 샘플이 없으면 깨끗·정밀·venue 적정 문체 기본값(범용 humanizer의 캐주얼·의견형 목소리 아님).

## Layer 6 — 제안서 모드

제안서는 논문이 아니다. **비전 + 실현가능성**으로 팔리며 심사위원이 채점한다. 논문 레이어가 깎을 야심 언어("장기 목표", "선도", "토대 구축")는 **제안서에선 적절 — 깎지 말 것**. 대신 **주장↔실현가능성** 규율을 강제한다.

> ⚠️ 리포지토리 Layer 6은 **NSF/NIH 골격**(Project Summary 3문두·Specific Aims 1페이지)이다. 한국 연구개발계획서(연구목표·추진체계·성과목표·추진전략)에는 **직접 매핑되지 않으므로**, 아래 **메타원칙만** 이식한다.

- **앞부분 최우선**: 심사위원은 앞 1~2쪽에서 점수를 형성한다. hook(왜 중요한가, 구체적으로)·gap(무엇이 없고 그 대가)·핵심 아이디어(한 문장)·목표/추진체계(간결·병렬)·payoff 를 앞에서 확보. 뒷장 손보기 전에 이걸 먼저.
- **method-as-aim 금지**: 목표가 기법명이 아니라 질문·성과로. "전이학습을 적용한다" → "웨어러블+실험 신호 융합이 조기검출을 개선하는지, 어느 하위집단에서 유효한지 규명".
- **도미노 목표 보강**: 1이 실패하면 2·3이 붕괴하는 구조는 취약 — **병렬·독립 가치**로 phrasing, 의존 시 fallback 명시.
- **야심에 실현가능성 결속**: 굵은 주장마다 근거(예비데이터·선행성과·고전정리·협력/LoI)를 붙인다. 없으면 지어내지 말고 저자에게 gap 을 flag.
- **정형 broader impact/교육계획 금지**: "학생 지도·논문 발표로 확산" 같은 상투구 → 구체·열거·연구 결속.
- **중심 가설의 과잉 헤징 금지**: 목표부 가설은 반증가능한 약속. 정밀 헤징은 접근방법 해석부에 둔다.

## 윤리·공개 (Ethics)

이 도구는 명료성·목소리 편집 보조이며 **발견을 생성하거나 데이터를 지어내지 않고 인용을 바꾸지 않는다**. **AI 사용 탐지·공개 회피용이 아니다.** 외부 투고 논문·제출 제안서에 적용할 경우 **투고처의 AI 사용 공개 정책을 준수**할 의무는 그대로다.

## Important

- 이미 잘 쓰인 문서면 그렇다고 말하고 최소 변경. 편집을 위한 편집 금지.
- 숫자·측정값·DOI·인용을 절대 건드리지 않는다(하나라도 바꾸면 결함).
- charcount 제한 문서(초록·요약·제안서 분량)는 편집 후 한도 확인.
- 개인 목소리 보정이 필요하면 이 커맨드가 아니라 [[Skills#Editing & Synthesis|/humanize]].
